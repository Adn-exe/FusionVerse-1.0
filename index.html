What is Machine Learning?

Machine Learning is a branch of Artificial Intelligence in which a computer learns a pattern(model) from data points(training examples), instead of being directly programmed with fixed rules(steps).

• In traditional computing, a computer is directly programmed with fixed rules and steps.

Understanding ML

The Core Types of ML Model

Most machine learning systems work using one of these core approaches.

There are 3 types of ML Model:

1. Linear Regression

2. Classification

3. Association

First we will look into Linear Regression

Type 01

Linear Regression (Predicting Numbers)

We are introducing an ML model in general to you using this type.

Linear Regression is a ML model that predicts a value that can change continuously, like a number on a scale, based on pattern(knowledge) in data. f(x)

f(x)
The Prediction Formula
y = mx + c

The equation represents a straight-line relationship between an input x and an output y, where m controls the slope and c controls the starting point.

m
The Slope (Steepness)
It tells the AI how much y should increase for every 1 step of x.
c
The Intercept (Starting Point)
It tells the AI where the line starts on the vertical axis when x is zero.
The Mathematical Proof (Linear Least Squares)
Formula for Slope (m)
m =
nΣxy - (Σx)(Σy) nΣx2 - (Σx)2
Formula for Intercept (c)
c =
Σy - mΣx n
n = Number of data points
Σ = Sigma (Sum of all values)

The "Statistical Error" (Inference Error)

AI doesn't "know" facts; it predicts them.

Technically, AI works on Probability Distributions. When our sample webapp generates a question, the model isn't "thinking"—it's calculating which word is statistically most likely to follow the previous one based on its training data.

Why this matters: This statistical nature leads to what we call Statistical Error or Hallucination. If the model sees a pattern that looks correct but isn't factually true, it might confidently give you a wrong answer. Always remember: AI is a powerful prediction engine, not a perfect truth machine.

What is Hugging Face?

Hugging face is a library of machine learning models (mostly of association type) on a public cloud. Each of these models can be accessed via a RESTful API.

An API is basically a URL with a variable part that can be substituted with some actual value/parameter.

Base Routing

All models on Hugging Face are accessed via a single endpoint:

https://router.huggingface.co/v1/chat/completions

In the request body, you simply specify the model name to determine which AI "brain" responds:

Payload from index.html
{
  "model": "deepseek-ai/DeepSeek-R1",
  "messages": [...],
  "token": "hf_..."
}
In server.js
const { model, messages, token } = payload;
const hfResponse = await fetch("https://router.huggingface.co/v1/chat/completions", {
    method: "POST",
    headers: { "Authorization": `Bearer ${token}` },
    body: JSON.stringify({
        model: model, // Tells the HF Router which model to use
        messages: messages
    })
});

Why a Proxy? The CORS Problem

You may now have a question: "Why are we using a server? Why can't the HTML page directly talk to Hugging Face?"

There are two major reasons. First, the security problem: your API key would be visible in the browser for anyone to steal. Second, the CORS problem: browsers block direct requests to Hugging Face for security reasons.

What is CORS? It's a browser security rule (Cross-Origin Resource Sharing). When your page at localhost:3000 tries to call another domain, the browser blocks it unless that domain explicitly permits it.

The Solution: Our Node.js server acts as a "Proxy" (a middleman). It securely holds your API key and handles the communication with Hugging Face, bypassing browser restrictions entirely.

Inside the Server: The Proxy Handler

Step 3 showed you the skeleton. Now let's look at the actual code inside the POST handler — this is where the server secretly talks to Hugging Face on behalf of your browser.

server.js — hover the dotted lines 
let body = "";
req.on("data", chunk => { body += chunk; });

req.on("end", async () => {
    const payload = JSON.parse(body);
    const { model, messages, max_tokens, token } = payload;

    // The actual API call to Hugging Face
    const hfResponse = await fetch(
        "https://router.huggingface.co/v1/chat/completions",
        {
            method: "POST",
            headers: {
                "Authorization": `Bearer ${token}`,
                "Content-Type": "application/json"
            },
            body: JSON.stringify({ model, messages, max_tokens })
        }
    );

    const data = await hfResponse.json();
    res.writeHead(hfResponse.status, { "Content-Type": "application/json" });
    res.end(JSON.stringify(data));
});

// Reusable helper — all 3 tabs call this
async function hfProxy(model, payload) {
    const token = getToken();
    const res = await fetch(
        `/hf?model=${encodeURIComponent(model)}`, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'x-hf-token': token
        },
        body: JSON.stringify(payload)
    });
    return await res.json();
}

Zero-Shot Classification (No Training Needed)

The most powerful tab is zero-shot classification. Unlike sentiment or emotion models that are trained on fixed labels, zero-shot lets you define your own categories on the fly.

What is zero-shot? The model (BART-large-MNLI) was trained to understand language relationships, not specific categories. So you can give it any labels — "politics", "cooking", "space" — and it will score how well the text matches each one. No retraining required!

index.html — zero-shot payload 
const data = await hfProxy(
    'facebook/bart-large-mnli',
    {
        inputs: "The striker scored in the 89th minute",
        parameters: {
            candidate_labels: [
                "politics", "sports", "science",
                "technology", "health"
            ]
        }
    }
);

// Response: { labels: ["sports", ...], scores: [0.97, ...] }

Part 4 — Troubleshooting

What if it breaks?

Coding is 10% writing code and 90% figuring out why it doesn't work. If your app isn't behaving, don't worry! Here are the most common "gotchas" and how to fix them.

The "White Screen" Mystery

If your page is completely blank, don't panic! Right-click anywhere and select Inspect > Console. The browser will show you red error messages that pinpoint the exact line where a typo might be hiding.

"Address already in use"

This error means another server is already hogging Port 3000. The Fix: Close all your terminal windows and restart, or edit server.js to use a different port like 3001.

401 Unauthorized Error

This is almost always a Token problem. Make sure your Hugging Face API key doesn't have any accidental spaces at the start or end when you copy it.

429 Too Many Requests

You're moving too fast for the free tier! Hugging Face limits how many messages you can send per minute. Simply wait 60 seconds and try again—it will reset automatically.

Still stuck? Don't worry!

If you've tried everything and it still isn't working, just raise your hand or reach out to the mentors. We are here to help you debug and get your AI running in no time!
