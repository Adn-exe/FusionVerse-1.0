Type 02

Classification

A Classification Machine Learning model is similar to a Regression model, except that its outputs (y values) are discrete categories instead of continuous numerical values.

  • Discrete values can only be from a finite set of values.
  • Examples of finite set:
    {Male, Female, Boy, Girl}
    {Pass, Fail}
    {A, B, C, D}
    {2.3, 4.1, 6.0}

Part 2

What is Hugging Face?

  • Hugging face is a library of machine learning models (mostly of generation type) on a public cloud. Each of these models can be accessed via a RESTful API.
  • — An API is basically a URL with a variable part that can be substituted with some actual value/parameter.

All models on Hugging Face are accessed via a single routing endpoint:

https://router.huggingface.co/v1/chat/completions

Each of our demo app consists of index.html page and a server.js (Proxy Server).

In the request body from index.html, you simply specify the model name that is then posted to server.js:

Payload from index.html
{
  "model": "deepseek-ai/DeepSeek-R1",
  "messages": [...],
  "token": "hf_..."
}
In server.js
const { model, messages, token } = payload;
const hfResponse = await fetch("https://router.huggingface.co/v1/chat/completions", {
    method: "POST",
    headers: { "Authorization": `Bearer ${token}` },
    body: JSON.stringify({
        model: model, // Tells the HF Router which model to use
        messages: messages
    })
});

The Proxy Server (server.js)

This server.js file does two things: (a) serves your HTML page, and (b) securely forwards requests to Hugging Face.

server.js — hover the dotted lines 
// 1. Load built-in Node.js tools
const http = require("http");
const fs   = require("fs");

const PORT = 3000;

// 2. Create the server
const server = http.createServer(async (req, res) => {

    // PART A: Serve the HTML page
    if (req.method === "GET") {
        fs.readFile("./index.html", (err, data) => {
            res.writeHead(200, { "Content-Type": "text/html" });
            res.end(data);
        });
        return;
    }

    // PART B: Forward AI requests to Hugging Face
    if (req.method === "POST" && req.url === "/analyze") {
        // ... Code that securely sends notes to Hugging Face API ...
    }
});

// 3. Start listening
server.listen(PORT, () => {
    console.log(`Server running at http://localhost:${PORT}`);
});
5

Why a Proxy? The CORS Problem

You may now have a question: "Why are we using a server? Why can't the HTML page directly talk to Hugging Face?"

There are two major reasons. First, the security problem: your API key would be visible in the browser for anyone to steal. Second, the CORS problem: browsers block direct requests to Hugging Face for security reasons.

What is CORS? It's a browser security rule (Cross-Origin Resource Sharing). When your page at localhost:3000 tries to call another domain, the browser blocks it unless that domain explicitly permits it.

The Solution: Our Node.js server acts as a "Proxy" (a middleman). It securely holds your API key and handles the communication with Hugging Face, bypassing browser restrictions entirely.

6

Inside the Server: The Proxy Handler

Step 4 showed you the skeleton. Now let's look at the actual code inside the POST handler — this is where the server secretly talks to Hugging Face on behalf of your browser.

server.js — hover the dotted lines 
let body = "";
req.on("data", chunk => { body += chunk; });

req.on("end", async () => {
    const payload = JSON.parse(body);
    const { model, messages, max_tokens, token } = payload;

    // The actual API call to Hugging Face
    const hfResponse = await fetch(
        "https://router.huggingface.co/v1/chat/completions",
        {
            method: "POST",
            headers: {
                "Authorization": `Bearer ${token}`,
                "Content-Type": "application/json"
            },
            body: JSON.stringify({ model, messages, max_tokens })
        }
    );

    const data = await hfResponse.json();
    res.writeHead(hfResponse.status, { "Content-Type": "application/json" });
    res.end(JSON.stringify(data));
});

Problem Statement: MoodWave

People often struggle to find music that truly matches their emotional state. Traditional music recommendation systems mainly rely on listening history, popularity, or genre preferences, but they fail to understand the user’s current mood and emotional context. This creates a disconnect between how users feel and the music they receive.

Build an AI-powered web application called MoodWave that analyzes a user’s emotional state from natural language input and generates a personalized playlist using a two-stage AI pipeline. The system should first understand the emotional tone, energy, and vibe of the user’s mood description, then generate a curated playlist of real songs that match the detected emotional atmosphere. The application should provide an immersive and interactive user experience with smooth animations, real-time pipeline visualization, and dynamically rendered playlist cards.

Suggested Features

  • • Mood description input using natural language
  • • Quick mood selection chips for faster interaction
  • • Two-stage AI pipeline visualization
  • • AI-generated music brief based on emotions
  • • Personalized playlist generation using LLMs
  • • Animated waveform/loading effects during processing
  • • Styled playlist cards with song title, artist, and genre
  • • Hugging Face token support using a proxy server
  • • Responsive modern UI with premium interactions
  • • Clear error handling and status indicators
Master Prompt

Build a single-file HTML app called MoodWave exactly similar to the attached index.html and server.js files. The app should use a sequential two-stage AI pipeline through the /analyze endpoint exposed by the proxy server. An asynchronous function in the HTML app should send the user’s mood description to the AI models through the proxy server and dynamically display the generated results. Stage 1 should use the model google/gemma-4-31B-it to analyze the user’s mood and generate a concise music brief describing the emotional texture, energy level, tempo feel, and 2–3 matching music genres or subgenres without recommending songs. Stage 2 should use moonshotai/Kimi-K2.5 to take the generated music brief and return exactly 7 real songs formatted as "Song Title" by Artist Name (Genre).
